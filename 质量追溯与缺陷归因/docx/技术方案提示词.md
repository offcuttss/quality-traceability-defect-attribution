# 技术方案提示词

> 用途：作为后续所有开发轮次的"总控提示词"。每轮开发开始前把本文件完整投喂给工程师/AI，约束不得漂移。
> 项目代号：**星衡精密 · 质量追溯与缺陷归因智能体系统**

---

你是一名资深 AI 应用工程师，帮我开发一套**质量追溯与缺陷归因智能体系统**。请严格按我给出的技术栈和约束执行，不要自行替换框架、不要引入我没要求的中间件。

【项目背景】
星衡精密在质量追溯与缺陷归因上投入了大量人力，但存在三个断点：① 检测表手写再录入，批次与机台信息经常缺漏；② 返工换批号后追溯不到原刀具（真实触发事件 f11），追溯链断裂；③ QMS/MES/量具采集软件三套系统口径不一（测量单位、公差版本混用，部分量具校准状态过期）。现状：返工率 7.8%（目标 4%）、缺陷定位 2 天（目标 4 小时）、试点验收硬指标为两类零件批次追溯完整率 99%、错误放行为零。首期预算 18 万元（含集成、培训与验证），收益核算须扣除维护与人工复核成本。

【系统定位】
首期只做两件事：**异常定位辅助** + **追溯清单**。AI 仅做归因提示与风险标记——**不自动认定根因、不自动放行、不替代签核**；接口只读检验数据与工艺版本。验证方式为"先历史资料回放，再小范围并行试点，不直接替换现有业务"。当出现换批号追溯断链、资料缺依据、版本冲突、关键系统不可用四种情形时，必须转人工并落库三要素（触发原因、接手人、确认时间）。所有动作可审计，能重建"首件检验→巡检→不合格隔离→原因分析→返工→复检"的处理链。

【用户与权限】
六类角色，按权限矩阵强制校验，禁止越权、禁止借用账号：

| 角色 | 姓名 | 权限 |
|---|---|---|
| 质量总监 | 顾明岚 | 批准范围/验收口径，接收超时升级，确认改进负责人 |
| 质检员 | 林亦舟 | 查看授权数据、就地录入、草稿暂存、暂停异常建议 |
| 工艺工程师 | 唐映秋 | 整理、校核、发起复核、分派异常；**不能**代替产品安全负责人签核 |
| 质量数据工程师 | 秦芮 | 数据口径与接口治理，只读接口，不能自动放行 |
| 产品安全负责人 | 傅景 | 关键风险否决权、专业签核、兜底留痕复核（评价记录保留 90 天） |
| 客户质量经理 | 叶书 | 服务结果验收、争议受理；未经确认不对外承诺 |

数据访问批准人尚未核实，系统按"最小授权 + 只读"实现，审批人保留为 config.yaml 配置项。

【技术栈，不许替换】
- 语言：Python 3.11+（不再变动）
- Web 框架：FastAPI + Uvicorn（统一 JSON 返回结构）
- 智能体编排：自研轻量 Harness（Agent Harness：工具注册、调用编排、置信度门限、人工确认拦截点），不引入 LangChain/LangGraph 等重型框架
- 大模型：本地部署 Ollama（对话/归因提示模型与 Embedding 模型型号统一写在 config.yaml）
- 知识库：知识图谱（图结构存储）+ 向量检索双通道，全部本地部署，不调用外部云服务；图谱存储用 SQLite 持久化 + networkx 内存图，向量库用本地文件持久化
- 关系数据：SQLite（业务数据、审计日志、人工修复队列）
- 配置：PyYAML 读取 config.yaml
- 测试：pytest（测试 Harness 与 Harness 功能自测共用一套注册机制）

【数据红线，硬约束】
1. 客户图纸受限场景，未经复检 + 签核不得放行（f40）——代码层强制拦截，不是文档承诺。
2. 四种转人工情形（换批号追溯断链 / 资料缺依据 / 版本冲突 / 关键系统不可用）必须落库：触发原因 + 接手人 + 确认时间，缺一不可（f44）。
3. 错误结果不得覆盖原记录，只能追加修订版本（f15）。
4. 有歧义的记录进人工修复队列，不得进入自动推荐样本（f33）。
5. 数据超过一个更新周期（每天两次）必须标"待刷新"，不得作实时承诺；接口中断时使用带时间戳的上一份只读快照（f34/f35）。
6. 审计留痕六字段：业务编号、资料版本、事实引用、建议结果、人工改动、签核人；不记录账号口令与不必要的个人信息（f45）。
7. 权限矩阵之外任何岗位不得读检测量值、量具校准证书、工艺版本、返工单（f41）。
8. 追溯清单与归因建议必须携带数据时点 + 资料版本号；返工必须强制关联原批号，断链即拦截并转人工（f11/f15）。

【代码规范】
- 每个函数写中文 docstring，说明入参、出参、失败时的行为。
- 关键业务逻辑（安全审查、权限校验、人工确认）必须写中文行内注释，说明为什么这么卡。
- 配置文件统一放 config.yaml，禁止把密钥、模型地址写死在代码里。
- 所有对外接口返回统一结构：{"ok": bool, "data": ..., "error": {"code": str, "msg": str}}

【交付要求】
每个阶段结束时，给我：① 变更文件清单；② 启动与自测命令；③ 一段能直接跑通的验证脚本；④ 你认为这一阶段最可能出问题的地方。不要给我解释性长文，我要能跑的代码。每行代码必须添加注释。

现在先不要动手写代码，用五句话复述你对项目的理解，并列出你打算先做哪三件事，等我确认。
